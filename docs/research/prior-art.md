## 2. Per-tool notes worth keeping

- process-compose is the most mature, actively released supervisor with REST, UDS, detached mode and an MCP server with opt-in control tools. It has zero knowledge of git, worktrees, port leasing or Docker. Project identity is the config file plus the chosen port or socket, so "same process twice" is solved only by happening to use the same socket path. Procly could embed or wrap it instead of writing a supervisor. Unverified whether its CLI refuses a second instance cleanly (source shows `--use-uds`, `--unix-socket`, `--detached`, `--keep-project` flags in `src/cmd/root.go`).
- devenv 2.x is the best "idempotent start" prior art: the attach-instead-of-fail semantics and the port holding during evaluation to avoid races are exactly Procly goals 1 and 2. Limits: Nix-only, per project dir, no worktree key, no compose driving.
- Portless (Vercel Labs, 12.7k stars in 8 months) shows large demand for the "stable named local URL per worktree" half. It does not dedupe processes or drive compose. A Procly user will likely run Portless alongside it, so Procly could emit `PORT_*` that Portless-style tooling consumes, or integrate via `portless alias`.
- Worktrunk is the de facto worktree manager (9.3k stars). Its port story is a stateless hash (collision possible) and its process story is `wt step tether`. Procly should integrate via hooks rather than compete.
- The "worktree plus docker compose isolation" niche already has 5+ young projects (falq, Docktree, wtc, workz, comport, denny-il/devenv). Only wtc and workz expose MCP. Only Docktree has the shared vs isolated notion (platform tier with per-worktree tenancy). None of them supervises host processes with dedup.

## 3. Coverage of Procly goals

| Goal | Best existing partial | Missing |
|---|---|---|
| 1. Idempotent start keyed on repo + worktree + service | Grove (worktree-aware, port-based detection of externals), devenv (attach to running), pz (name uniqueness with `--replace`) | A key of exactly (repo, worktree, service) with a durable registry on Linux and macOS, no GUI dependency |
| 2. Free-port leasing per worktree with env injection | workz (registry in `ports.json`, `PORT_<SERVICE>`), falq (slot ranges), Docktree (pool), devenv (probe plus hold) | Lease semantics on actual liveness (probe free ports, expire dead leases) combined with process supervision |
| 3. Avoid duplicate containers, shared vs isolated per service | Docktree (platform shared tier plus isolated), wtc/falq/workz (isolated only) | Per-service mode flag driving compose with per-worktree project names AND dedup of already-running shared containers across worktrees, combined with host process supervision |
| 4. Agent CLI/API/MCP, macOS + Linux | process-compose (REST + UDS + MCP, cross platform), workz and wtc (MCP, worktree-aware), Docktree (`--json` plus skills) | One tool with all three surfaces; process-compose MCP is not worktree aware |

## 4. Closest to Procly

1. Grove: same product thesis (agents should call a CLI instead of spawning their own dev servers, worktree-aware, detects externally started servers, takeover). Gap: macOS-only menu bar app owning the processes, no Linux, no port leasing (ports fixed in config), no Docker or compose handling, no MCP, no declared license, 1 star.
2. workz (with Docktree as the compose-side twin): per-worktree port registry, env injection, compose project name, MCP server, `reap` of stale port holders. Gap: does not supervise or dedup host processes (only sets env and kills by port), no shared-vs-isolated service mode (Docktree has it but without MCP and without process supervision).
3. process-compose: the engine candidate. Gap: no git/worktree identity, no port leasing, no Docker compose driving, MCP is generic and project-scoped.

## 5. Open items and caveats

- Star counts and dates from `gh` on 2026-10-18. `gh search repos` returned nothing for several multi-word queries, so the long tail of tiny worktree-port tools is under-sampled. Web search results for the worktree space are vendor blogs, treat as marketing.
- I did not read license text of Worktrunk (listed "Other" by GitHub, README badge says MIT OR Apache-2.0) or Superset ("Other").
- Name collisions to note for Procly branding: none checked. Also note mprocs was renamed dekit (repo `pvolok/dekit`), `Crystal` renamed Nimbalyst.
