# React, bun and oxc for the frontend of the desktop app, checked by `make check`

The desktop app renders the `Response` documents its Rust poller emits every 2 to 30 seconds, follows the output of one Service or Job through a `Channel`, and draws about 9 screens in one window. It holds no logic of its own (ADR 0009), so the frontend is a renderer of keyed lists that change often. Svelte was weighed against React: its smaller bundle matters little in a webview loaded from disk, while React is the stack the maintainer and coding agents write most fluently, and the oxc tools cover it fully. TypeScript with no framework was rejected because it means writing the keyed updates of the DOM by hand.

The frontend is therefore React 19 with strict TypeScript, built by Vite as a single-page app under `apps/desktop/`, with no Next, no router, since the screens are a state of the app rather than URLs, and no state library: the last `Response` of the poller is read through `useSyncExternalStore`.

- **Packages.** bun is the one package manager of the project. Only `bun.lock` is committed, `packageManager` in `apps/desktop/package.json` pins the version of bun, and `bun install --frozen-lockfile` fails when the lockfile and `package.json` disagree. A contributor may run npm or pnpm locally, but `package-lock.json` and `pnpm-lock.yaml` are ignored by git, and only `bun.lock` counts.
- **Node.** Node LTS is pinned in `apps/desktop/.node-version` and required next to bun, because Vitest runs on Node. Vitest run by bun with no Node installed hung until a recent, undated fix.
- **Checks.** The frontend enters the existing targets of `make check`, so the local run and the CI keep executing the same commands. `fmt-check` runs `oxfmt --check`, `lint` runs `oxlint`, with its `react`, `react-hooks` and `typescript` plugins, and `tsc --noEmit`, and `test` runs Vitest with React Testing Library, jsdom and `mockIPC` from `@tauri-apps/api/mocks`. `oxlint` and `oxfmt` are the pair another project of the maintainer already runs. They are pinned to exact versions and upgraded together, since `oxfmt` is still 0.x and a minor release can reformat code, with the reformatting committed in the same change.
- **Protocol types.** `procly-client` derives TypeScript types with `ts-rs` behind a `ts` feature, exported during `cargo test` into `apps/desktop/src/protocol/`. The generated files are committed, and `make test` fails with `git diff --exit-code apps/desktop/src/protocol` when they are stale, so a protocol change the frontend has not followed becomes a TypeScript error. `tauri-specta` was rejected while its v2 is a release candidate, and hand-written types would drift silently.
- **Cargo.** `apps/desktop/src-tauri` stays a member of the workspace, built by every `--workspace` command. Tauri's `generate_context!` panics at compile time, under `clippy` and `doc` too, when `frontendDist` does not exist, so the `build.rs` of `src-tauri` writes a placeholder `dist/index.html` that names `bun run build` when `dist/` is missing. `dist/` is ignored by git, and `tauri build` always replaces the placeholder through `beforeBuildCommand`.
- **CI.** Both jobs of `ci.yml` install bun with `oven-sh/setup-bun`, which reads `packageManager`, and Node with `actions/setup-node`, which reads `.node-version`, then run `bun install --frozen-lockfile` in `apps/desktop`. The Ubuntu job also installs the system packages Tauri needs on Linux (`libwebkit2gtk-4.1-dev`, `libayatana-appindicator3-dev`, `librsvg2-dev`, `libxdo-dev`, `libssl-dev`). The `make` steps do not change.
- **Supply chain.** `security.yml` gains a `bun audit --audit-level=high` job over every dependency, devDependencies included, triggered by `apps/desktop/bun.lock` and on the weekly schedule, since Vite, Vitest and the oxc tools run in the release workflow that holds the signing secrets. Dependabot gains a `bun` entry for `/apps/desktop`, weekly and grouped, with `oxlint` and `oxfmt` in a group of their own.

React, Vite and oxc are not vendored in `docs/reference/`: their APIs are stable and well known, unlike Tauri v2, whose v1 APIs are easily recalled by mistake.

## Consequences

- `make check` needs bun, Node and, on Linux, the WebKitGTK packages, even for a change that only touches the Daemon. `CONTRIBUTING.md` lists them.
- A fresh clone builds with `cargo` alone, but the app it builds shows the placeholder page until `bun run build` has run.
- A change to the socket protocol lands with its regenerated TypeScript types in the same change, or `make test` fails.
- The release workflow, which builds and signs the bundle, is decided with the developer account and the distribution channel, not here.
